##  Rôle du Firewall
Le firewall de **pfSense** contrôle le trafic entre les différentes interfaces réseau et applique des règles de sécurité pour le WAN/LAN/pfsense et ses services:

### WAN (Internet / VirtualBox NAT)
- Interface : **em0**
- Adresse IP : obtenue automatiquement (DHCP) (**192.168.122.61**)
- Rôle :
	- protéger le réseau local contre les connexions provenant d'Internet ;
	- permettre à pfSense d'accéder à Internet (DNS, NTP, mises à jour).
### LAN (Réseau interne GNS3)
- Interface : **em1**
- Adresse IP : **192.168.1.1/24**
Rôle :
	- fournir une passerelle aux machines du réseau local ;
	- permettre aux postes Windows et Ubuntu d'accéder à Internet ;
	- distribuer les adresses IP via le serveur DHCP ;
	- fournir le service DNS grâce au DNS Resolver.
### pfSense
pfSense assure également plusieurs services réseau :
- Firewall
- NAT
- DHCP Server
- DNS Resolver
- WebGUI d'administration
Le firewall décide quels paquets sont **autorisés** ou **bloqués** selon l'interface sur laquelle ils arrivent.


# Règles par défaut de pfSense
pfSense applique automatiquement des règles de sécurité après son installation.
## LAN → Any : Autorisé
Une règle **Pass LAN net → Any** est créée automatiquement.
Elle autorise les machines du LAN à communiquer avec :
- Internet
- pfSense
- DNS
- DHCP
- autres réseaux
- ICMP (ping)
Cette règle permet aux machines Windows et Ubuntu de sortir sur Internet.

## WAN → LAN : Bloqué
Aucune règle d'autorisation n'est présente sur l'interface WAN.
Conséquence :
- toutes les connexions provenant d'Internet sont bloquées.
Le réseau local est ainsi protégé contre les connexions non sollicitées.

## WAN → pfSense : Bloqué
Par défaut, l'accès au pare-feu depuis Internet est interdit.
Les services suivants ne sont pas accessibles :
- WebGUI
- SSH
- ICMP
- autres services d'administration

Exceptions automatiques :
- DHCP (si nécessaire)
- DNS
- NTP

# Fonctionnement du Firewall

### 1. Windows / Ubuntu → pfSense
✅ Autorisé
Les postes peuvent joindre leur passerelle :
```text
192.168.1.1
```
### 2. Windows / Ubuntu → Internet
✅ Autorisé
Le trafic est autorisé par la règle **LAN → Any** puis traduit par le NAT.

### 3. Internet → Windows / Ubuntu
❌ Bloqué
Les connexions initiées depuis le WAN sont refusées.

### 4. Internet → pfSense
❌ Bloqué
L'administration de pfSense n'est pas accessible depuis Internet.

### 5. pfSense → Internet
✅ Autorisé
Nécessaire pour :
- DNS
- NTP
- mises à jour
- téléchargement de paquets

#  Configuration du firewall

### 1. Accéder à l’interface web de pfSense

1. **Depuis Windows/Ubuntu du LAN**
    - Ouvre ton navigateur.
    - Aller sur :
        ```
        https://192.168.1.1
        ```
    - Identifiants par défaut : 
        - **user:** `admin`
        - **password:** `pfsense`
### 2. Configurer les interfaces WAN et LAN

#### **WAN (em0 en DHCP)**
1. Menu :
    ```
    Interfaces
        WAN
    ```
2. Paramètres :
    - **Interface:** cochée
    - **IPv4 Configuration Type:** `DHCP`
    - Laisse le reste par défaut.
3. Clique sur **Save**, puis **Apply Changes**.
#### **LAN (em1 en 192.168.1.1/24)**
1. Menu :
    ```
    Interfaces
        LAN
    ```
2. Paramètres :
    - **IPv4 Configuration Type:** `Static IPv4`
    - **IPv4 Address:**
        ```
        192.168.1.1
        ```
    - **Subnet mask:** `24` (255.255.255.0)
3. Clique sur **Save**, puis **Apply Changes**.
### 3. Configurer le NAT (sortie Internet)

1. Menu :
    ```
    Firewall
        NAT
            Outbound
    ```
2. Choisis :
    ```
    Automatic Outbound NAT rule generation
    ```
3. Clique sur **Save**, puis **Apply Changes**.

pfSense créera automatiquement les règles NAT pour que le LAN sorte vers le WAN.
### 4. Configurer le serveur DHCP du LAN

1. Menu :
    ```
    Services
        DHCP Server
    ```
2. Onglet **LAN**.
3. Coche **Enable DHCP server on LAN interface**.
4. Plage d’adresses :
    ```
    Range:
    192.168.1.100
    to
    192.168.1.199
    ```
5. **Gateway:**
    ```
    192.168.1.1
    ```
6. **DNS servers:**
    ```
    192.168.1.1
    ```
7. Clique sur **Save**.
### 5. Activer le DNS Resolver

1. Menu :
    ```
    Services
        DNS Resolver
    ```
2. Coche :
    ```
    Enable DNS Resolver
    ```
3. Laisse les options par défaut (écoute sur LAN).
4. Clique sur **Save**, puis **Apply Changes**.
### 6. Configurer les règles firewall LAN

Menu :
```
Firewall
    Rules
        LAN
```
Par défaut, tu as une règle “Allow LAN to any”. Tu peux la garder ou la rendre plus explicite.

#### **Règle 1 — Autoriser LAN vers Internet**

- **Action:** `Pass`
- **Interface:** `LAN`
- **Address Family:** `IPv4`
- **Protocol:** `Any`
- **Source:** `LAN net`
- **Destination:** `any`
- **Description:** `Autoriser LAN vers Internet`

Clique sur **Save**, puis **Apply Changes**.

_(Optionnel avancé : on pourrait ensuite ajouter des règles plus fines, mais pour ton labo, celle‑ci suffit.)_

### 7. Vérifier les règles firewall WAN

Menu :
```
Firewall
    Rules
        WAN
```
Par défaut, pfSense bloque tout ce qui vient du WAN.
Vérifie :
- qu’il n’y a **aucune règle “Pass”** vers le LAN ou vers `LAN net`,
- que les règles par défaut sont de type **Block/Reject**.
Ne crée **aucune règle** autorisant l’accès au LAN depuis le WAN.

# Tests du Firewall

## Depuis Windows ou Ubuntu

Vérifier la communication avec pfSense :
```bash
ping 192.168.1.1
```

Vérifier l'accès Internet :
```bash
ping 8.8.8.8
```

Vérifier la résolution DNS :
```bash
ping google.com
```

## Depuis la console pfSense
Choisir :
```text
7) Ping host
```

Puis tester :
```text
8.8.8.8
```
## Vérification de l'adresse LAN
Depuis le shell pfSense :
```sh
ifconfig em1
```

Résultat attendu :
```text
inet 192.168.1.1 netmask 0xffffff00
```
## Test de blocage WAN → LAN

Depuis le réseau WAN, il doit être impossible d'accéder à :
```text
https://192.168.1.1
```
ou à une machine du LAN :
```text
192.168.1.x
```

Comportement attendu :
- connexion refusée ;
- aucun accès au réseau interne.
Cela confirme que le pare-feu protège correctement le LAN contre les connexions entrantes.
