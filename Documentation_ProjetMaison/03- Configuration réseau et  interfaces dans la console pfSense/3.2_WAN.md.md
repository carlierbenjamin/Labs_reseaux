## Rôle : interface qui connecte pfSense à Internet (via NAT VirtualBox). 
Ici, le WAN est connecté au **NAT de VirtualBox**, qui joue le rôle de “fournisseur Internet”.
Pour configuer le WAn il faut Dábord ajouter un NAT au projet : dans GNS3 desktop, glisser un NAT (voir 'EndDevice'). Puis ajouter un lien entre pfSense (em0) et NAT (voir 'AddLink'). Le lien doit être vert après configuration du WAN.
Notes: 
vérifier dans virtalBox, dans les paramètres de la GNS3 VM, les 2 cartes réseau :
- **Adaptateur 1 : WAN**
  - Type : **NAT (VirtualBox)**
  - Rôle : accès Internet
- **Adaptateur 2 : LAN**
  - Type : Réseau privé hote
vérifier dans pfsense (clic droit -> configure -> Network -> configure custom):
**Adapter 0**  
**
## Configuration dans la console pfSense
Menu pfSense -> Option **1**
Should VLANs be set up now [y|n]? n
Enter the WAN interface name or 'a' for auto-detection : em0
Enter the LAN interface name or 'a' for auto-detection : em1
Enter the Optional 1 interface name or 'a' for auto-detection or nothing if finished : press enter
Do you want to proceed? [y|n] y

puis: 
Menu pfSense -> Option **2**
Configurer le WAN (em0) : option 1
Configure IPv4 via DHCP? y
Configure IPv6 via DHCP? n
Enter the new WAN IPv6 address. Press ENTER for none: press enter
Do you want to revert to HTTP as the webConfigurator protocol? n

## Problèmes fréquents
Vérifications :
1.Vérifier que le lien WAN avec GNS3 est bien établi :
    - Dans GNS3, le câble entre le **NAT** et **em0** doit être vert.
    - Si le lien est rouge ou absent, supprimer le câble et reconnecter le nœud NAT à **em0**.

2. Vérifier l'état du WAN :
    - Depuis la console pfsense, choisir  Shell.
    - commande :
      *ifconfig em0*
On doit obtenir :
- inet 192.168.122.61 
- status: active
- media: 1000baseT full-duplex
Problèmes fréquents :
- pas d'adresse IPV4 
- status :  no carrier (= cables non branché)
C’est exactement ce qui arrive quand :
- le WAN n’est pas connecté au bon nœud dans GNS3 (voirt lien entre pfSense et NAT dans GNS3 desktop => lien doit être vert)
- l’adaptateur VirtualBox n’est pas en mode NAT
- Hyper‑V bloque les cartes réseau
    - commande :
	    *dhclient em0*
	    puis :
	    *ifconfig em0*

## Problèmes fréquents
### 1. Pas d’IP WAN
Symptôme : WAN = 0.0.0.0  
Solution : vérifier que l’adaptateur 1 de pfSense est en **NAT** dans GNS3.

### 2. pfSense ne démarre pas / WAN inactif
Symptôme : WAN ne reçoit aucune IP  
Cause : Hyper‑V activé sur Windows Host  
Solution : désactiver Hyper‑V :
- Panneau de configuration → Programmes → Activer/désactiver des fonctionnalités Windows → décocher Hyper‑V  
ou  
- Shell : 
*bcdedit /set hypervisorlaunchtype off*


### 3. Internet fonctionne sur pfSense mais pas sur Windows/Ubuntu
Symptôme : pfSense ping 8.8.8.8 mais les VM non  
Solution : vérifier que Windows/Ubuntu utilisent pfSense comme passerelle :
- Passerelle : **192.168.10.1**
