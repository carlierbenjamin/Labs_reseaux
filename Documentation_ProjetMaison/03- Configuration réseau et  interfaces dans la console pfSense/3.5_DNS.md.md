
##  **Rôle du DNS dans le laboratoire**19
pfSense joue le rôle de **DNS local** pour le réseau LAN `gns`. 
Les machines du LAN utilisent pfSense pour résoudre les noms de domaine (ex : `google.com`). Donc conversion des noms de domaines en adresses IP.
ex: Quand une machine LAN (Windows ou Ubuntu) veut accéder à un site web, elle envoi une requete google.com et pfSense envoi l'IP correspondante.

Le DNS local permet :
- de centraliser les requêtes DNS
- de filtrer ou contrôler les résolutions (si nécessaire)
- d’éviter que les machines LAN interrogent directement Internet
- d’améliorer la cohérence du réseau

**Explications:** 
L’adresse DNS local fournie par le DHCP de pfSense est :
```
192.168.1.1
```
Lorsqu’une machine LAN demande une connexion à un site web (ex : google.com),
pfSense :
1. reçoit la requête DNS du client/périphérique LAN (Windows server/Ubuntu Client)
2. consulte son DNS Resolver et résout les noms de domaines en IP (s'il les connait)
3. si nécessaire, **redirige** les requêtes vers des DNS publics via le WAN
    - Google DNS : `8.8.8.8`
    - Cloudflare : `1.1.1.1`
    - DNS du FAI (selon VirtualBox NAT)

Ce mécanisme s’appelle :
 **DNS Forwarding** ou **DNS Resolver (Unbound)**
=> pfSense utilise **Unbound**, activé par défaut.

## 1) **Fonctionnement DNS dans le lab**
### Étape 1 — Windows / Ubuntu envoient une requête DNS

```
ping google.com
```
### Étape 2 — pfSense reçoit la requête

À l’adresse :
```
192.168.1.1
```
### Étape 3 — pfSense résout ou relaie

- soit via son cache DNS
- soit via les DNS publics configurés sur le WAN
### Étape 4 — pfSense renvoie l’IP au client

Le client peut alors contacter le serveur Internet.


## 2) Configuration du DNS pfSense

### 2.1) Ouvrir le Shell pfSense

### 2.2) Vérifier si le DNS Resolver (Unbound) tourne

Unbound est le service DNS interne de pfSense. S’il n’est pas actif, le LAN ne peut pas résoudre les noms.
- Exécuter : 
	```
	ps aux | grep unbound
	```
- Si tu vois un processus `unbound`, le DNS est actif
- Si rien n’apparaît (ex: root 1150 ... grep unbound) → Unbound n’est pas lancé
### 2.3)Démarrer ou redémarrer Unbound

Si Unbound n’est pas actif, tu dois le lancer manuellement.
- Démarrer : `/usr/local/sbin/unbound-control start`
- Redémarrer : `/usr/local/sbin/unbound-control reload`
- Vérifier : `/usr/local/sbin/unbound-control status`


### 2.4)Vérifier les DNS système

pfSense doit avoir des DNS externes pour que sa console puisse résoudre les noms.

- Exécute : `cat /etc/resolv.conf`
- Si tu vois `nameserver 127.0.0.1` → Unbound n’écoute pas sur localhost
- Si tu vois `nameserver 192.168.122.1` → DNS du NAT VirtualBox (non joignable)
- Si le fichier est vide → pfSense n’a aucun DNS
    
### 2.5)Ajouter des DNS externes (méthode console)

Tu peux ajouter des DNS externes temporairement pour tester la résolution.
- Ajouter Cloudflare : `echo "nameserver 1.1.1.1" >> /etc/resolv.conf`
- Ajouter Google : `echo "nameserver 8.8.8.8" >> /etc/resolv.conf`
- Vérifier : `cat /etc/resolv.conf`


##  3)**Tests DNS**

### 3.1)Tester la résolution DNS

vérifier si pfSense peut maintenant résoudre un nom de domaine.
- Test : `nslookup google.com`
- Test : `dig google.com`

-### **Résultat attendus**
- Si on vois une IP (ex : 142.250.xxx.xxx) → **DNS OK**
- Si on vois `network unreachable` → **pfSense n’a pas de DNS système**
- Si on vois `SERVFAIL` → **Unbound ne répond pas**
- Si on vois `REFUSED` → **Unbound n’écoute pas sur localhost**

### 3.2)Vérifier que Unbound écoute sur les bonnes interfaces

Unbound doit écouter sur LAN et idéalement sur localhost pour la console.
- Exécute : `sockstat -4 | grep 53`

-### **Résultat attendus**
- On dois voir :
    - `unbound ... 127.0.0.1:53`
    => DNS pour la console pfSense
    - `unbound ... 192.168.101.1:53`
	=> DNS pour les autres clients LAN (Windows, Ubuntu, Cisco)
- Si localhost n’apparaît pas → activer dans l’interface Web
###  3.3) Test DNS et Internet sur Windows Server
```
nslookup google.com
ping google.com
```
###  3.4) Test DNS et Internet sur Ubuntu
```
dig google.com
ping google.com
```

## 4) Problèmes fréquents

### 1) Unbound refuse de demarrer
- Symtome : 
	-Unbound essaie d’ouvrir : **::1:53** (IPv6 localhost) → impossible → il n’ouvre **aucun port** -> message erreur :
	*error: can't bind socket: Can't assign requested address for ::1 port 53
	**fatal error: could not open port*s
- Solution: 
	-enlever IPv6 des interfaces Unbound\

Se connecter a l'interface web de pfsense  (=IP LAN de pfSense = 192.168.1.1) via un navigateur (ex: chrome/edge de la VM windows server)  (configuré précédemment) :
http://192.168.1.1 
=> avertissement de certificat -> pfSense utilise un certificat auto-signé.
Cliquer :
- **Avancé**
- continuer vers 192.168.1.1

Identifiants par défaut :
- **Username :** admin
- **Password :** pfsense


Dans l’interface Web pfSense
#### 4.1.1️ Aller dans
- ###### Status -> interface:
verifier le status du WAN et LAN :
WAN -> status: up, IPv4 : 192.168.122.61, gateway : 192.168.122.1
LAN -> status: up, IPv4 : 192.168.1.1

- System → General Setup->  **DNS Server Settings**.
Renseigner les serveurs publics les plus connus pour trouver les noms de domaines.  
'addDNS server' pour chacun ci-dessous :
- **DNS Server 1 : 1.1.1.1**, hostname: vide (pour server Cloudflare)
- **DNS Server 2 : 8.8.8.8** (Google)
- **DNS Server 3 : 9.9.9.9** (Quad9)
important :
-**Décocher pour chaque server : Allow DNS server list to be overridden by DHCP/PPP******
(Sinon VirtualBox NAT va écraser tes DNS avec ceux du réseau hôte).
-save pour enregistrer

- **Services → DNS Resolver**
Pour activer/configurer DNS resolver,
On dois cocher :
- ✔️ **Enable DNS Resolver**
- ✔️ **Listen Port : 53**
- ✔️ **Network Interfaces : All
- ✔️ **Outgoing Interfaces : WAN**
- ✔️ **Enable DNSSEC Support** (optionnel)
- ✔️ **Enable Forwarding Mode** (recommandé pour un lab=> Pour que pfSense puisse  **transmettre** les requêtes aux DNS externes (plus rapide et plus simple).
-cliquer sur l'onglet apply change (onglet vert => changes successfully)

- **Services → DHCP Server → LAN**
Vérifier le DHCP pfSense, Dans la section DNS :
- Si c’est vide → pfSense met automatiquement **192.168.1.1** (subnet range) et **192.168.1.1**00-192.168.1.199 (address poll range)
