# 3. Problèmes fréquents + Solutions
## 3.1 Problèmes QEMU (= ~ Système exploitation de virtualisation) / Virtualisation

Si pfSense ne démarre pas dans QEMU :
### Hyper‑V activé (cause principale)
Symptôme : pfSense reste bloqué, QEMU affiche des erreurs. 
ex : « KVM acceleration cannot be used (/dev/kvm doesn't exist)

### Solution (Windows)
- **Désactiver Hyper‑V** de Windows Host (rôle d'installer un Hyperviseur de type 1 exécuté avant Windows) dans le shell avec la commande : 
		*bcdedit /set hypervisorlaunchtype off*
- **Désactiver VBS** de Windows Host (rôle de sécurité du noyau Windows basée sur la virtualisation (VBS)) :
	- Paramètres -> Sécurité Windows -> Sécurité de l’appareil -> Isolation du noyau -> OFF

- Vérifier si Hyper-V est encore actif avec la commande dans le shell :
		*Get-CimInstance -ClassName Win32_DeviceGuard*
	A la ligne : '*VirtualizationBasedSecurityStatus*' si - **0** -> VBS désactivé
										   - **1 ou 2** -> VBS encore actif -> désactiver Device guard

- **Désactiver Device Guard** (Device Guard est un ensemble de mécanismes de sécurité avancés dans Windows 11 ayant pour objectif d' empêcher l’exécution de code non approuvé en utilisant  la virtualisation) avec les commandes suivantes dans le shell :
*reg add "HKLM\System\CurrentControlSet\Control\DeviceGuard" /v EnableVirtualizationBasedSecurity /t REG_DWORD /d 0 /f* 
*reg add "HKLM\System\CurrentControlSet\Control\DeviceGuard" /v RequirePlatformSecurityFeatures /t REG_DWORD /d 0 /f* 
*reg add "HKLM\System\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 0 /f*

- Vérifier si hyper-V est inactif avec la commande dans le shell : 
	*bcdedit /enumv*
Résultat attendu : **hypervisorlaunchtype Off**

## 3.3. Problèmes crash pfsense/VM mal etient ou instabilité de version pfsense

=> 
- La partition `/cf` est **corrompue**, mais **le fichier de configuration est encore lisible**.
- Le système de fichiers ne peut plus être réparé (superblock détruit).
- pfSense **ne peut plus booter correctement**.
- essayer de récupéré **le fichier de configuration ** : `config.xml`.

sur  console pfsense, copier le fichier de configuration 'conf' :
```
mount -u /
mount -a
ls /cf/conf/
```
le résultat doit etre :
```
backup
config.xml
copynotice_version
copyright
rules.debug.old
upgrade_log.txt
```
Note: 
fichier configuration copié dans** `/tmp/config.xml` **avec succès.**


Solution : 
1/réinstaller pfSense

2/Recréer une VM propre

3/Installer pfSense 
4/ verifier emplacement du fichier conf dans la console shell pfsense:
ls -l /conf/
on y voit: 
	/conf/config.xml
	/conf/backup/

4/Verifier la connexion SSH sur líntreface pfsense
4.1- connexion a l'**interface web** pf sense:
Se connecter a l'interface web de pfsense  (=IP LAN de pfSense = 192.168.1.1) via un navigateur (ex: chrome/edge de la VM windows server)  (configuré précédemment) :
http://192.168.1.1 
=> avertissement de certificat -> pfSense utilise un certificat auto-signé.
Cliquer :
- **Avancé**
- continuer vers 192.168.1.1

Identifiants par défaut :
- **Username :** admin
- **Password :** pfsense
4.2-Dans l’interface Web :
```
System → Advanced → Admin Access
```
Descends jusqu’à **Secure Shell** et vérifie :
✔️ **Enable Secure Shell** est coché ✔️ Port = **22** ✔️ Login group = **admins** (par défaut)
Sauvegarde si nécessaire.

5/Récupérer `/conf/config.xml` depuis pfSense vers Windows Server
5.1. Installe **WinSCP** sur ton Windows Server.
5.2. Ouvre WinSCP.
5.3. Connecte-toi à pfSense :
    - **Host** : l’IP LAN de pfSense (ex : 192.168.1.1)
    - **User** : `root`
    - **Password** : pfsense
    - **Protocole** : SFTP
5.4. Une fois connecté, ouvre le dossier :
```
/conf/
```
5.5. Tu verras le fichier :
```
config.xml
```
5.6. **Glisse-dépose** ce fichier vers ton Windows Server (ex : Bureau, Documents, etc.)

6/ restaurer le config.xml : 
6.1- connexion a l'**interface web** pf sense:
6.2- Dans l’interface web pf sense :
Menu :
```
Diagnostics
    Backup & Restore
```
Section **Restore** :
- Choisis ton fichier `config.xml` (chemin vers =>'  /conf/config.xml`)
- Clique **Restore Configuration**
=> pfSense va redémarrer et le réseau sauvegardé devrait être intact
