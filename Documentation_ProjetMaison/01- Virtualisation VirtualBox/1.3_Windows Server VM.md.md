
# 1. Télécharger l’image ISO Windows Server (officiel Microsoft)

## Windows Server 2022 (recommandé car stable)

### Étapes :

1.  site officiel Microsoft : **Microsoft Evaluation Center**
https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2022
2. Choisir : **Download the ISO**
3. Remplis le formulaire (nom, email, pays)
4. Télécharge le fichier 64-bit edition: **Windows_Server_2022.iso**
=>  ISO d’environ **5 Go**.

# 2. Créer la VM Windows Server dans VirtualBox

### Étape A — Nouvelle VM
- Nom : **WindowsServer2022**
- Type : **Microsoft Windows**
- Version : **Windows 2022 (64-bit)** 
### Étape B — RAM / CPU
- RAM : ** 3072 MB (3 Go)**
- CPU : **2 vCPU**
### Étape C — Disque
- Crée un disque virtuel : **40 Go**
- Format : **VDI**
- Mode : **Dynamically allocated**
### Étape D — Carte réseau
#### Adaptateur 1 :
- **Réseau interne**/**Internal Network**
- Nom : **LAN** 
- Adaptater Type : Intel PRO/1000 MT Desktop
- Promiscuous Mode : Refuser
#### Adaptateur 2 : désactive
### Étape E — Monter l’ISO
Dans **Storage**/Stockage :
- Clique sur le lecteur optique
- Choisis : **Windows_Server_2022.iso**
- ajouter:  WindowsServer2022.vdi

#  3. Installer Windows Server
.vdi
Démarrer la VM → installation classique :
1. Choisir **Windows Server 2022 Standard Evaluation (Experience de bureau/Desktop Experience)**
2. Accepter la licence
3. Installation personnalisée
4. Choisir le disque de 40 Go
5. Attendre la fin
6. Créer un nom ("*Administrateur*") et  mot de passe admin : "*AdminWindowsServer2022*"

=> affichage du bureau Windows Server OK.=> **ctrl droite + del** 

#  4. Ajouter la VM dans GNS3

### Étape A — GNS3 → Preferences
- Edit → Preferences
- VirtualBox → VirtualBox VMs -> local computer
- Clique sur **New**
- Sélectionne **WindowsServer2022**
### Étape B — Ajouter dans ton projet
Dans GNS3 :
- Clique sur l’icône **PC / VM**
- Glisse **WindowsServer2022** dans ton lab

#  5. Connecter Windows au switch LAN

Dans GNS3 :

- pfSense em1 → switch port 1

# 7. Evolution possible du projet avec Windows Server

## 7.1) **Contrôleur de domaine (Active Directory)**

 => rôle principal** 

On peut transformer la VM windows Server en :
- **AD DS** (Active Directory Domain Services) = pour **centraliser, organiser et sécuriser** tout ce qui concerne les utilisateurs, les ordinateurs et les ressources d’un réseau
- **DNS Windows** (obligatoire pour AD) = noms de domaine local (ex : ben.local)
- **DHCP Windows** (optionnel) = adressage
- **Serveur d’authentification** (Kerberos)
- **Serveur LDAP** = annuaire, pour authentification, gestion des utilisateurs, permissions, applications, sécurité.
    

### Ce que ça peut ajouter : 

- Un domaine : `ben.local`
- Des comptes utilisateurs centralisés
- Des machines jointes au domaine
- Des GPO (politiques de sécurité)
- Une architecture proche d'une entreprise **réelle**
## 7.2) **Serveur DNS interne (si tu déploies AD)**

Si tu installes Active Directory, ton Windows Server devient automatiquement **le DNS principal** du réseau interne.
Parce que AD utilise des enregistrements DNS spéciaux :
- SRV
- LDAP
- Kerberos
- Sites & Services

pfSense ne sait pas gérer ça
pfSense reste donc :
- DNS forwarder
- Firewall
- NAT
- DHCP (si tu veux)

## 7.3) **Serveur DHCP (optionnel)**

Tu peux déplacer le DHCP de pfSense vers Windows Server.
### Avantages
- Intégration avec AD
- Réservations dynamiques
- DHCP failover (si tu ajoutes un 2ᵉ serveur)
- Options avancées (PXE, VoIP, VLANs)

### Inconvénients
- Plus complexe
- Moins utile si pas de AD

## 7.4) **Serveur de fichiers (File Server)**

On peut créer :
- des partages SMB
- des permissions NTFS
- des dossiers par utilisateur
- des dossiers par service
- des quotas
- des snapshots

## 7.5) **Serveur WSUS (Windows Update Services)**

Pour gérer les mises à jour de toutes les machines Windows du réseau.
Utile si on veut simuler un vrai environnement IT.

## 7.6) **Serveur RADIUS / NPS**

Pour authentifier :
- routeur Cisco
- switchs
- VMs
- Wi‑Fi (si on ajoutes un AP virtuel)

On peux faire du **AAA** comme dans les entreprises.
=> Authentication – Authorization – Accounting
=> **système de contrôle d’accès centralisé** utilisé dans les réseaux professionnels pour gérer :
1. **Qui** peut se connecter
2. **Ce qu’il peut faire**
3. **Ce qu’il a fai**
## 7.7) **Serveur web (IIS)**

Pour héberger :
- un site interne
- une application web
- un portail intranet
- un serveur de test

## 7.8) **Serveur PKI (certificats)**

Pour gérer :
- certificats internes
- authentification forte
- HTTPS interne
- VPN avec certificats
